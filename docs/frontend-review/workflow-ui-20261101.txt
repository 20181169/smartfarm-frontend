담당자
1. 계획평가에서 대상 계획을 선택하고 '이 계획의 활동 등록' 클릭.
2. 작성 기준 계획·한글 작업 유형·기간 확인. 증빙을 선택하면 활동일과 계획 기간을 즉시 비교.
3. 활동 제출 후 검토 대기 상태 확인. 반려되면 상세의 반려 사유를 보고 같은 활동을 수정·재제출.
4. 활동 목록의 연결 계획을 클릭하면 해당 계획으로 이동.
5. 계획 상세의 '이 기간의 보고서'에서 기간을 이어받아 조회·PDF 생성.
6. 보관 목록의 승인 상태와 검토 의견 확인 후 PDF 다운로드.

검수자
0. 로그인 첫 화면의 '검토할 자료 찾기'에서 '영농활동 검토' 또는 '보고서 검토·서명' 선택.
   같은 이름의 메뉴도 사이드바 상단에 배치. 활동은 검토 대기 목록, 보고서는 보관 PDF 목록부터 표시.
1. AI 증빙에서 분석 결과와 검토 이력을 보고 증빙 확정 또는 반려.
2. 영농이행 활동 상세에서 증빙·활동 내용을 확인.
3. 조건이 맞는 계획을 선택하고 '활동 확정 및 계획 연결'. 반려에는 사유 입력 필수.
4. 활동 확정 후 연결만 실패하면 '계획 연결 다시 시도'. 활동 승인 요청을 중복 전송하지 않음.
5. 계획 기간 종료 다음 날부터 최종 이행 평가 입력 가능.
6. 각 PDF의 '보고서 검토·서명'을 눌러 기간·파일명·PDF를 확인하고 승인 또는 반려. 승인 대상은 특정 보관 PDF.

관리자
- 관할 발전소를 선택하고 동일 계획·활동·증빙·보고서 연결 결과 조회.
- 기존 권한에 따른 검토 기능 유지. 검수자의 보고서 승인 후 관리자 추가 승인은 필수 단계가 아님.

기존 API 사용
- GET /farming-plans, GET /farming-plans/{id}/matches: 활동 목록에 실제 연결 계획 표시.
- POST /farming-activities: 담당자의 활동 제출. 요청 스키마 변경 없음.
- PATCH /farming-activities/{id}/review: 활동 확정 또는 반려.
- POST /farming-plans/{id}/matches: 검수자의 실제 계획 연결 저장.
- 증빙·평가·보고서·승인 API도 기존 계약 유지.

프론트만 수정할 때의 한계
- 담당자가 선택한 '작성 기준 계획'은 화면 간 전달 정보이며, 제출 시 계획 연결 요청 필드로 서버에 저장되지 않음.
  검수자는 실제 연결할 계획을 별도로 선택. 서버 연결이 완료된 상태만 '연결 완료'로 표시.
- 활동 확정과 계획 연결은 서로 다른 서버 요청. 부분 완료·응답 유실을 재조회하고 연결만 재시도.
- 계획과 연결된 확정 활동의 유형·기간이 어긋나는 수정은 이 화면에서 사전에 차단.
  다른 API 클라이언트에서 변경하거나 증빙을 사후 반려했을 때 서버 집계 유효성을 재계산하는 문제는 백엔드 과제.
- 웹 보고서 승인 기록이 기존 PDF 파일의 서명란을 바꾸지는 않음. PDF 원문과 웹 승인 기록을 구분해 안내.
