화면과 계정
1. admin으로 로그인 → 사이드바 '카메라 설정' (/#/camera-settings)
   - 발전소 선택, 카메라 장비 등록, DB 카메라 장비 목록
   - 메인/보조 RTSP, 스트림 식별자, TCP/UDP, 사용 여부, PTZ/ONVIF 설정 정보
   - 조회 주소는 백엔드 masked 필드만 표시
   - 원본 주소는 비밀번호 입력칸에만 보관, 로그·storage에 저장하지 않음
   - 저장 요청 후 성공/실패와 관계없이 원본 주소 입력값 제거
   - 기존 주소를 조회할 수 없으므로 수정 시 메인 주소 재입력 필요
   - 기존 보조 주소가 있는 경우 재입력 또는 명시적 제거 선택 필수

2. '자동 촬영 정책' (/#/capture-policies)
   - 정책 목록/상세/등록/수정, enabled 비활성화·활성화
   - 새 정책은 비활성 시작; 사용으로 저장하면 실제 서버 자동 촬영 대상이 됨
   - 시간대 배열, 목표 횟수, 카메라 배열, 우선순위, 항목별 사용 여부
   - 동일 발전소 영농계획 선택 → 작업 유형·적용 기간 채움
   - 계획 상세 '이 계획의 자동 촬영 설정'으로 계획 문맥을 전달
   - 이벤트 ON/OFF, ANY/ALL, 감지 주기, 중복 촬영 방지 시간, 탐지 규칙 배열
   - 감지 주기 5~86400, 중복 방지 0~86400, 신뢰도 0~1
   - 시간대 겹침/역전, 중복 클래스·카메라, 다른 발전소/비활성 장비·취소 계획 차단
   - 이벤트 ON일 때 활성 규칙 1개 이상 필수. 문서의 경고 권장보다 서버 검증이 강함
   - 정기 촬영을 원하지 않으면 시간대 항목 사용 해제; API는 시간대 1개 이상 요구

3. 'CCTV 트랙터 인식' (/#/cctv)
   - 기존 업로드/수동 분석/증빙 상세/원본·결과 이미지/확정·반려/이력 유지
   - 촬영일·검토 상태·탐지 대상 검색, 검색 초기화와 페이지 이동
   - 촬영일 없는 증빙은 서버 기준에 따라 분석일로 검색
   - 촬영 시각, 카메라, 출처, 탐지 수, 상세 최대 신뢰도 표시
   - DB 장비 조회 권한이 있으면 카메라 이름, 없으면 API의 카메라 ID 표시
   - 검수된 증빙 → 활동 제출·검토 → 계획 연결·평가 → 보고서 승인 기존 흐름 유지
   - 자동 촬영·분석은 증빙 검수나 활동 확정을 자동으로 수행하지 않음

구현 범위와 제약
- 기존 /vision/cameras는 Vision 설정 파일 목록, 새 자동 촬영은 DB devices/runtime 기반
- 자동 촬영 설정에는 /devices에서 type=camera인 동일 발전소 장비만 사용
- Vision Analysis 응답에는 event_triggered/policy_id/event_trigger_id가 없으므로
  정기/이벤트 촬영 배지를 추정하지 않음. 조회 API가 추가되면 확장 가능
- Scout 상태 조회·daemon 제어·실시간 RTSP 재생·실제 PTZ 제어는 구현하지 않음
- '설정됨/미설정/사용/비활성'만 표시. 장비 온라인·영상 정상으로 추정하지 않음
- 로컬 시연 화면 /farming-workspace의 브라우저 자료와 운영 API 자료는 계속 분리
- 촬영 정책의 farming_plan_id는 영농활동의 확정·매칭을 대신하지 않음
- 백엔드 소스·권한·운영 데이터 변경 없이 프론트만 수정
- 구현 검증은 배포 전에 수행. master push 이후 기존 GitHub Actions로 자동 배포
