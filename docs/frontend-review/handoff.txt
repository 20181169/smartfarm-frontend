프론트 요구사항 반영 결과 (2026-10-21)

수정 범위: smartfarm-frontend. 백엔드 소스·DB·권한 데이터는 변경하지 않음.
문서 기준: 로컬 구현·검증 결과. 커밋·푸시 상태는 Git 기준이며 운영 배포 결과는 별도 확인 필요.

1. 공통 — 하위 권한 계정에 데모 데이터 노출
   발전소현황: 실발전소 목록은 유지하고 데모 카드만 제한.
   종합대시보드: 실발전소를 기본으로 표시. 허용된 계정만 데모 전환 가능.
   사업장상세·이상징후: 현재 전체가 데모이므로 비허용 계정에는 연결 준비 안내 및 실제 계획평가 링크 표시.
   허용 기준: SYS_ADMIN 또는 서버 /regions 응답에서 활성 강원특별자치도/강원도 관할이 확인되는 PROVINCE_ADMIN.
   지역 조회 실패·권한 누락·다른 시도·하위 관리자는 데모를 표시하지 않음. 계정 이름이나 레벨로 관할을 추정하지 않음.
   영농이행 화면도 운영자에게 다른 발전소의 예시 정상 판정이 표시되던 부분을 같은 기준으로 제한.
   PDF 보고서의 요청받은 벼 4단계·75%·8회 고정값은 유지.

2. 공통 — CCTV 이번 세션 분석 로그
   세션별 고유 순번으로 결과를 선택. frame_id 누락·중복과 최근 30개 목록 교체로 선택한 결과가 바뀌는 문제 방지.
   클릭하면 선택한 결과 영역으로 이동하고 포커스 표시.
   서버 저장 이력을 새로 조회하는 별도 목록 및 상세 조회 연결.

3. 공통 — JSON 다운로드와 자동 저장 구분
   버튼 명칭을 '분석 결과 JSON 다운로드'로 변경.
   백엔드 origin/main 8651794의 /vision/detect 및 /vision/cameras/{camera_id}/detect는
   save_vision_analysis를 호출한 후 analysis_id를 반환함. JSON 버튼과 무관하게 분석 API에서 저장.
   analysis_id가 반환된 경우에만 서버 저장 안내. JSON은 로컬 사본 다운로드.

4. INSPECTOR — 분석 실행 금지, 검토 유지
   서버 vision:run 보유 여부와 관계없이 INSPECTOR의 분석 입력·실행을 프론트에서 제한.
   vision:read / vision:review에 따라 저장 이력 조회 및 검토 결과 저장 화면 연결.
   GET /api/v1/vision/analyses?plant_id=...
   GET /api/v1/vision/analyses/{analysis_id}
   GET /api/v1/vision/analyses/{analysis_id}/image/annotated
   PATCH /api/v1/vision/analyses/{analysis_id}/review
   검토는 사용자 선택 후 저장. AI 자동 확정하지 않음.
   [백엔드 필요] 기존 RBAC 문서는 INSPECTOR에 vision:run을 부여하고 서버는 그 permission을 검사함.
   프론트 차단과 별개로 직접 API 호출도 금지하려면 서버의 해당 역할 권한을 조정해야 함.

5. 공통 — 설정 API 점검
   실제 /auth/me 이름·이메일·역할, 발전소 이름·조회 가능한 인버터 모델 표시.
   예시 번호 XXXX, 임의 계약값, 알림 시간·수신 옵션, 가짜 저장 성공 버튼 제거.
   미연동 항목은 준비 중 표시.
   [백엔드 필요] 본인 연락처/프로필 수정, 경보 수신 시간·조건, 카카오 수신자,
   발전소 계약 주체·제도·REC 가중치·보유량, 갱신 주기 설정의 전용 조회·저장 API.
   사용자관리 PATCH /users/{id}는 별도 관리자 권한 기능이며 본인 알림/계약 설정 저장 API를 대체하지 않음.

6. PLANT_OPERATOR — 영농계획 작성 기능 없음
   계획평가 화면에 영농계획 작성·등록 연결. 영농이행 화면에서 계획평가로 이동 가능.
   POST /api/v1/farming-plans (farming_plan:create 필요)
   API에 허용된 발전소 목록만 선택. 계획명·활동유형·설명·일/주/월/기간 및 날짜 입력.
   등록 성공 후 목록 재조회 및 생성한 계획 선택. 실패 시 성공 안내하지 않음.
   [협의] 수기 영농활동 등록은 별도 필요 여부 확인 항목으로 구현하지 않음.
   CCTV 분석 저장이 영농활동 확정을 의미하지 않음. 활동 등록·검토·계획 매칭·평가는 별도 절차.

7. 공통 — 보고서 메뉴 PDF 개발/GPT 필요 여부
   /report의 발전·수익 분석 보고서는 현재 예시 지표/문장과 가짜 PDF 다운로드 alert로 구성됨.
   다운로드 버튼은 준비 중으로 변경. 새 발전·수익 PDF나 GPT 기능은 추가하지 않음.
   /compliance-report의 영농이행 PDF 생성·다운로드는 이미 별도 API와 연동되어 있음.
   [협의] 발전·수익 보고서의 실제 데이터·분석 범위·PDF 양식을 먼저 정해야 함. PDF 출력 자체에 GPT는 필수가 아님.

8. 공통 — 이행리포트 다운로드 경고
   기존 프론트는 인증된 API 응답을 Blob으로 받아 다운로드함.
   운영 주소는 HTTP이고 2026-10-21 HTTPS 접속 확인은 실패함.
   [서버 확인] 정확한 브라우저 경고 유형 확인 후 도메인/TLS 인증서/HTTPS 프록시·API 경로 설정 검토.
   브라우저 보안 경고를 숨기거나 보안 설정을 해제하는 코드는 넣지 않음.

9. 별도 결정 필요
   영농이행/계획평가 메뉴 통합 여부, 운영자의 발전소비교/종합대시보드 메뉴 필요 여부.
   INSPECTOR 온라인 서명: 온라인 서명 방식과 저장·승인 API 연결은 별도 확인 필요.
   현장점검 시정명령·추가 증빙 요청: 추가 API 및 처리 흐름 필요.

검증
   운영 /openapi.json에서 계획 생성과 분석 이력·검토 API 배포 확인.
   제공받은 관리자·광주 운영자 계정의 실제 /auth/me, /plants, /farming-plans,
   /vision/analyses 및 상세 조회 성공. 운영 계획 생성/분석 실행/검토 저장은 하지 않음.
   브라우저 테스트에서는 API 응답을 대체해 저장 성공·403·입력 오류·권한별 노출을 검증.
   구현은 실제 API 클라이언트를 사용하며 모의 API는 테스트에서만 사용.
   node --test tests/ui-policy.test.mjs: 3개 통과.
