# 로컬 사진 기반 영농관리

진입: 사이드바 **영농관리 · 로컬 시연**, 경로 `/#/farming-workspace`.
전체 앱은 저장된 다크 테마 설정과 관계없이 흰색 테마를 사용합니다.

## 가능한 흐름

1. 발전소 담당자 화면: 벼 재배계획과 4단계 일정·장비·인력·작업 가이드를 작성합니다.
2. 사진 갤러리에서 작업 증빙을 선택합니다. 논 분류 확률과 트랙터 탐지 박스를 확인할 수 있습니다.
3. 계획 단계별 수행 내용과 전·후 논 사진을 연결해 기록합니다.
4. 기간별 보고서 초안을 생성하고 종합 의견을 입력해 검토를 요청합니다.
5. 상단 시연 역할을 검토자로 전환해 보고서 전체를 확인하고 보완 요청 또는 승인합니다.
6. 보완 요청 시 담당자가 보고서의 내용·사진을 변경하고 같은 보고서를 재제출합니다.
7. 승인 시 승인 시각·의견을 기록하고 최종 PDF 인쇄가 활성화됩니다.
8. 현장 확인 탭에서 검토자가 시정 요청을 기록하고 담당자가 조치 내용을 남길 수 있습니다.

## 저장 범위

- 이미지: `public/demo/farming/` 아래 정적 파일.
- 실제 AI 출력값: `public/demo/farming/analyses.json`.
- 계획·수행 기록·보고서·검토 이력: 브라우저 localStorage, 계정 및 선택 발전소별 분리.
- 제출·보완·승인은 로컬 시뮬레이션이며 서버 권한이나 실제 전자서명을 대신하지 않습니다.
- 브라우저 자료를 지우면 입력한 내용도 없어집니다. 다른 PC와 공유되지 않습니다.
- 별도 API 저장 호출이 없으며 기존 운영 영농이행·계획평가·이행리포트 화면은 유지합니다.

## 샘플과 실제 기능 구분

논 사진 28장은 기존 학습 체크포인트로 CPU 추론했고, 트랙터 사진 1장은 기존
Grounding DINO 분석 결과 및 박스 이미지를 가져왔습니다. 분류값을 임의로 만들지 않았습니다.
초기 4장과 트랙터 사진의 촬영일은 미등록입니다. 추가 24장은 기존 데이터셋의 촬영 날짜·관측지·출처 URL을 함께 보관합니다. 갤러리 날짜 필터는 분석일 기준입니다.
서로 다른 촬영 장소를 포함하므로 선택한 전·후 사진은 실제 현장 변화의 증명이 아닙니다.

계획의 초기 일정·가이드는 편집 가능한 예시이며 AI 가이드 생성 API는 미연동입니다.
카메라 자동 수집, 센서·기상 자동 이상 판정, 운영 DB 저장, 실제 승인·전자서명은
백엔드 계약 확정 후 연결해야 합니다. 현재 보고서는 샘플 표시를 포함합니다.

## 구성

- `src/lib/localFarming.js`: 로컬 자료 읽기·쓰기, 보고서 스냅샷과 상태 전이.
- `src/views/FarmingWorkspaceView.jsx`: 계획·갤러리·기록·보고서·현장 확인.
- `src/views/FarmingWorkspaceView.css`: 반응형 화면과 여러 페이지 인쇄 레이아웃.
- `scripts/prepare-local-farming.py`: 로컬 사진 복사 및 실제 논 모델 재분석 도구.

자료 재생성 예시 (논 AI 실행 의존성이 설치된 Python 사용):

```text
python scripts/prepare-local-farming.py --rice-root <논모델프로젝트> --vision-root <백엔드의vision폴더>
```

  사진 변경·재제출 → 승인 → PDF까지 확인했습니다.
- 새로고침 후 이력 유지, 모바일 가로 넘침 없음, 필터 빈 결과, 원본·박스 전환 확인.
- 생성한 PDF는 2페이지이며 마지막 페이지의 전후 사진·종합 의견·검토 의견을 확인했습니다.
- 브라우저 검증 과정에서 backend 쓰기 요청 0건.

커밋·푸시·운영 배포는 별도입니다.

## 단계별 갤러리와 계획 연결

- 사진 분류 버튼: 전체 사진 / 파종·모내기 / 영양생장 / 출수·개화 / 수확기 / 작업 증빙 / 이상징후 후보.
- 논 사진은 실제 `analysis.rice_stage.stage` 값으로 분류합니다. 농기계 탐지만 있는 사진은 작업 증빙에 표시합니다.
- 알 수 없거나 누락된 단계는 미분류로 표시하며, 신뢰도가 낮은 결과에는 확인 필요 표시를 붙입니다.
- 계획의 각 단계에서 **해당 단계 사진 보기**를 누르면 그 단계의 분류가 열리고 수행 기록 단계도 이어집니다.
- 갤러리에서 다른 분류를 보거나 작업 증빙을 선택해도 연결할 계획 단계와 선택한 사진은 유지됩니다. 연결 단계는 별도 선택 상자에서 변경할 수 있습니다.
- 분류와 연결 단계는 URL에 유지됩니다. 검색 초기화는 검색어·분석일만 초기화합니다.
- 현재 샘플 분포: 파종·모내기 9장, 영양생장 4장, 출수·개화 10장, 수확기 5장, 작업 증빙 1장. 총 29장입니다. 빈 단계를 채우기 위해 판독값을 임의 변경하지 않습니다.
- 추가 브라우저 검증: 4단계 계획 링크, 분류별 사진 수, 빈 분류, 저신뢰도 표시, 새로고침 시 분류·단계 복원, 분류 간 선택 유지, 수행 기록의 단계·증빙 저장, 보고서 초안, 모바일 가로 넘침, 검토자 조회 전용. API 쓰기 요청 0건.


## 확장 사진과 이상징후 후보

- `scripts/extend-local-gallery.py --rice-root <논모델프로젝트> --vision-root <백엔드vision폴더>`로 기존 모델의 테스트용 사진 24장을 추가합니다. 기존 사진 ID와 브라우저 기록은 유지합니다.
- 추가 사진은 `rice_stage_unified_v3/test`에서 가져왔습니다. 폴더 라벨을 정답처럼 표시하지 않고 실제 재추론 결과에 따라 분류합니다. 테스트 데이터 재사용이므로 독립적인 모델 성능 검증을 의미하지 않습니다.
- 이상징후 후보 3장은 화면 흐름을 위한 명시적인 시연 시나리오입니다. 실제 질병·관수 이상·미활동을 탐지한 결과가 아닙니다.
- 후보는 해당 생육 단계에도 중복 표시합니다. 후보 수는 전체 사진 수에 추가 합산하지 않습니다. 낮은 분류 신뢰도만으로 이상 후보를 생성하지 않습니다.
- 검토자 시연 역할에서 후보의 **현장 확인 요청**을 누르면 사진과 요청 사유가 **현장 확인** 작성 화면으로 전달됩니다. 버튼 클릭만으로 저장하지 않으며 **현장 확인 요청 기록**을 눌러 저장합니다.
- 담당자가 조치를 기록하면 갤러리에도 조치 상태가 표시됩니다. 기존 요청이 있는 사진은 **현장 확인 보기**로 연결하여 중복 요청을 막습니다.
- 이후 생성하는 보고서에는 요청 사진·내용·조치 기록이 포함됩니다. 이미 생성한 초안은 생성 당시 스냅샷을 유지합니다.
- 검증: 빌드 및 16개 테스트 통과. 실제 브라우저에서 29장 로드, 7개 분류, 후보→현장 요청→새로고침→담당자 조치→보고서 포함, 모바일 레이아웃 확인. API 쓰기 요청 0건.

배포 전 최종 검증: HTTP 환경에서 UUID 대체 생성 및 계획 저장·갤러리 표시 확인. 단위 테스트 총 17개와 배포 빌드 통과. 기존 API 연결·자동 배포 설정은 변경하지 않았습니다.


## 상세 작업 가이드 (2026-11-13)

영농계획 작성·수정 및 저장된 계획에서 단계별 `상세 보기`를 열어 사용합니다.
사진 분류는 기존 4단계를 유지하며, 가이드는 아래 12개 세부 작업으로 구성합니다.

| 단계 | 세부 작업 |
| --- | --- |
| 파종·모내기 | 종자·육묘 준비 / 논 정지·용배수 준비 / 모내기·초기 상태 확인 |
| 영양생장 | 활착·생육 상태 관찰 / 물관리·용배수 점검 / 시비·잡초·병해충 관리 기록 |
| 출수·개화 | 출수·개화 상태 기록 / 기상·환경 변화 확인 / 등숙 진행·후속 관리 |
| 수확기 | 수확 일정·장비 준비 / 수확·반출 작업 / 작업 마무리·보고서 준비 |

각 작업에는 작업명, 예정일, 작업 시점·일정 조정 기준, 목적, 준비 사항,
수행 순서, 확인 항목, 사진·기록 안내가 있습니다. 담당자 화면에서 편집하고
영농계획 저장으로 보관합니다. 검토자 화면에서는 조회만 가능합니다.

벼 이앙재배를 가정한 업무 계획 예시입니다. 품종·지역·재배 방식별 맞춤 추천이나
AI 가이드 생성은 아직 제공하지 않습니다. 비료·약제 투입량, 물 깊이 등 처방값은
고정하지 않습니다. 월별 예시 가이드에서 재배 시작일·단계별 날짜·세부 작업 예정일을 자동 입력합니다.
기본은 읽기 전용이며, 별도 일정 조정 버튼을 열어 변경하고 사유를 남깁니다.
생육 시기별 물관리 용어 참고: [농촌진흥청 농사로 물관리 영상](https://www.nongsaro.go.kr/portal/ps/psb/psby/vodPlay.ps?mvpNo=2201).
작업 카드와 증빙·보고서 안내는 이 서비스의 시연 흐름에 맞춰 작성한 예시입니다.

기존 저장 계획의 ID·일정·장비·인력·메모를 보존하며, 새 작업 배열이 없는 계획에는
기본 상세 가이드를 표시합니다. 계획을 수정 저장할 때 작업 배열도 저장합니다.
이미 작성된 보고서 스냅샷은 변경하지 않습니다. 저장 위치와 운영 API 연결은 기존과 같습니다.

추가 파일: `src/lib/localFarmingGuide.js`, `src/views/FarmingGuide.jsx`.
검증: 전체 단위 테스트 24개, 배포 빌드, 브라우저 편집·재조회·기존 계획 호환·검토자 조회·
모바일 화면·갤러리 이동을 확인했습니다. 브라우저 검증은 외부 API 요청을 차단한 환경에서 수행했습니다.


### 월별 가이드 우선 계획 작성

- 새 계획은 재배 연도별 가이드 일정이 기본 적용됩니다. 11~12월에는 다음 재배 연도를 기본 선택하며 연도 변경이 가능합니다.
- 5월 육묘·논 준비 → 5월 말~6월 초 모내기 → 6~7월 생육 관리 → 8~9월 출수·개화·등숙 → 10월 수확·마무리의 시연 흐름입니다.
- 일별 날짜(예: 6월 5일 모내기, 10월 10일 수확)는 시연 계획의 입력 기본값입니다. 현장 품종·지역별 공식 권장일이나 AI 예측이 아닙니다.
- ‘가이드 일정으로 영농계획 저장’을 기본 동작으로 제공합니다. 날짜 입력은 잠겨 있고 ‘현장 사정으로 일정 조정’을 누르면 편집 가능합니다. 기준 일정과 다른 경우 사유가 필요합니다.
- 연도 선택 후 ‘가이드 일정 적용’을 눌러야 실제 계획 날짜가 바뀝니다. 적용 시 기존 메모·장비·인력·작업 내용·계획 ID는 보존합니다. 날짜와 조정 사유만 가이드 기준으로 초기화합니다.
- 기존 저장 계획은 자동 변경하지 않습니다. 기존 날짜로 저장하거나 직접 가이드 적용을 선택할 수 있습니다. 과거 보고서 스냅샷도 유지합니다.
- 지역·품종별 가이드 API가 연결되면 예시 재배력을 대체해야 합니다. 지역·품종별 이앙 시기가 달라지는 점은 [농촌진흥청 모내기 안내](https://www.rda.go.kr/board/board.do?boardId=farmlcltinfo&currPage=202&dataNo=100000802719&mode=updateCnt&prgId=day_farmlcltinfoEntry&searchEDate=&searchKey=&searchSDate=&searchVal=)를 참고했습니다. 현재 날짜표 자체는 이 자료의 공식 재배력이 아닙니다.
